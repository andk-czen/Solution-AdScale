# Стратегия масштабирования

## Сервис ставок (Bidding Service)
Масштабирование: горизонтальное - добавление новых узлов
Репликация БД: для PostgreSQL - Master‑Slave. Master — для записи (обновления лимитов, статусов), Slave — для чтения данных кампаний и таргетинга.
Шардирование не требуется. Возможно в дальнейшем после накопления больших архивов данных.
Read Replicas: да, 2–3 реплики для распределения запросов на чтение. 
CQRS не требуется

## Сервис кампаний (Campaign Service)
Масштабирование: горизонтальное.
Репликация БД: Master‑Slave для PostgreSQL, где Master — запись изменений кампаний; Slave — чтение статичных данных для UI и отчётов.
Шардирование: по ID_кампании при росте числа рекламодателей.
Read Replicas: реплика для поддержки фронтенда, реплика для API‑запросов.
CQRS возможно, но не в первую очередь:
- Command Model — создание/редактирование кампаний (запись в Master);
- Query Model — чтение данных для UI из реплик.

## Сервис статистики (Stats Service)
Масштабирование: горизонтальное.
Репликация БД: встроенная репликация ClickHouse.
Шардирование: по дате и ID_кампании.
Ключ шардирования: комбинация campaign_id + дата для равномерного распределения нагрузки.
Read Replicas: не требуются — ClickHouse дает возможность для распределённого чтения.
CQRS излишне.

## Сервис аналитики (Analytics Service)
Масштабирование: горизонтальное.
Репликация БД: ClickHouse - реплицированные шарды (2–3 копии);
Шардирование: ClickHouse - по дате + tenant_id;
Ключи шардирования: ClickHouse - tenant_id;
Read Replicas не требуется.
CQRS излишне.

## Сервис финансов (Financial Service)
Масштабирование: горизонтальное.
Репликация БД: PostgreSQL, где
* Master — все транзакции (списания, резервирования);
* Slave — отчёты, аудит, чтение балансов.
Шардирование возможно, при повышении нагрузки.
Read Replicas: 2–3 реплики для отчётов по балансам, дашбордов для рекламодателей, аудита финансовых операций.
CQRS стоит применять для:
* Command Side — финансовые транзакции (запись в Master с ACID‑гарантиями);
* Query Side — чтение балансов и отчётов из Slave‑реплик.

##Итог
Можно использовать CQRS везде, где разделение нагрузки на чтение-запись даст ощутимый прирост (все сервисы, кроме сервисов аналитики, статистики и ставок).
ClickHouse предоставляет широкие возможности для горизонтального масштабирования стандартными средствами.
